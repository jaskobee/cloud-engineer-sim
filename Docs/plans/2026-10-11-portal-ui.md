# Portal-style UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current single-screen layout with a shell and workflow modelled on the Azure portal. The game layer
(ticket, clock, map, Guided paths) docks into that shell.

**Architecture:**
- A pure route model (`src/ui/portal/route.ts`) lives in the session, and a working pane renders the current route.
- Service menus, wizard tabs and portal paths are data. Every label in them cites a PORTAL rule in
  `Docs/AZURE_FACTS.md`.
- Fluent UI React v9 supplies the controls and the theme. The engine and mission logic don't change; the only additions
  are mission data fields.

**Tech Stack:** React 19, TypeScript 6.0, zustand 5, Fluent UI React v9 (`@fluentui/react-components`,
`@fluentui/react-icons`), @xyflow/react (lazy), Vitest 5, Playwright 1.63.

**Spec:** `Docs/specs/2026-10-11-portal-ui-design.md`

**Execution:** Jasko approved the spec and asked for it to be built "without stopping and asking". It runs natively (the
executing-plans skill), with one fresh review of the whole change at the end.

## Global Constraints

- **Accuracy:** no portal label, tab name, menu item or path step is shown without a PORTAL rule that cites Learn
  (spec §6). An unverified label is left out.
- **No fakes:** controls for things the sim doesn't model are left out: Copilot, Cloud Shell, Support + Troubleshooting,
  Feedback.
- **Branding:**
  - The header shows "Cloud Engineer Simulator" and a "Simulation" badge.
  - No Microsoft logo and no "Microsoft Azure" wordmark.
  - Azure architecture icons stay governed by D-5.
- **Typography:** Fluent 2 web ramp, Segoe UI: body 14/20, caption 12/16, subtitle 20/26, title 24/32.
- **Separation:**
  - `src/engine` and `src/missions` logic stay unchanged. Mission data may gain `portalPath` fields.
  - The boundary test stays green.
- **The UI changes the world only through `store.dispatch`** (rule 2).
- **Derived, not stored:** notifications and breadcrumbs are derived. The session stores only the route, back stack, map
  flag, context pane, ticket open/closed and the notifications watermark.
- **Release gate:** `npm run check` and `npm run test:e2e` are green before every push.
- **Dependencies:** pin exact versions for the Fluent packages.
- **Narrow screens:** below 900 px there's no horizontal page scroll, and the ticket becomes a drawer.

## Review Focus

1. **Stale routes.** A route that points to a resource that was deleted, or to one that's still `Creating`, must render
   "This resource no longer exists" or the creating state, never crash.
   → Covered by the "missing resource" case in the Task 5 test.
2. **Back stack after create.** After Create → Go to resource → back, you should land on the deployment page or the list,
   not in a half-filled wizard with stale values.
   → Covered by the `goBack after create` case in the Task 2 test.
3. **Saved games.** An old save has no `nav` in the session. The session isn't saved, but continuing must start on Home
   with nothing broken.
   → Covered by the e2e "save and continue" test (Task 10).
4. **Refusals in the wizard.** A refusal found on Review + create must show the rule, and the right tab must stay
   reachable to fix it. The Create button stays disabled until a fresh validation passes.
   → Covered by Task 6 test `review then edit invalidates`.
5. **Mission paths that point at nothing.** A Guided path step whose target resource doesn't exist yet (e.g. "nsg-web"
   before it's created) must render as plain text, not as a dead link.
   → Covered by Task 9 test `unresolved target renders as text`.

### Task 2: Route model and store navigation

**Files:**
- Create: `src/ui/portal/route.ts`
- Modify: `src/store/gameStore.ts`
- Test: `tests/ui/route.test.ts`, `tests/store/gameStore.test.ts`

**Interfaces:**
- Produces:
  - `Route`, as in spec §5, plus `{ page: 'createPicker' }` for the "Create a resource" type list.
  - `ContextPane`, one of:
    - `{ kind: 'create'; request: CreateRequest }` (subnet / securityRule / webTest / metricAlert child forms and edits);
    - `{ kind: 'flow'; flowId: string }`.
  - `Nav = { route; back: Route[]; map: boolean; contextPane: ContextPane | null; ticketOpen: boolean; notificationsSeenAt: number }`
  - `sameRoute(a, b): boolean`
  - `breadcrumbFor(route, world): { label: string; route: Route | null }[]`
  - `routeForResource(id: ArmId, world): Route`. A child resource routes to its parent's section: a subnet goes to the
    VNet's `subnets` section, a security rule to the NSG's `inbound`/`outbound` section.
  - Store actions:
    - `navigate(route)` pushes the current route onto `back`, unless the route is the same;
    - `goBack()`; `toggleMap(on?)`; `openContextPane(p)`; `closeContextPane()`; `setTicketOpen(b)`;
      `markNotificationsSeen(simMs)`.
  - Compatibility, so the existing components keep working until they're replaced:
    - `select(id)` = `navigate(routeForResource(id))`, or `openContextPane({kind:'flow'})` for `flow:` IDs;
    - `startCreate(req)`: `null` → `goBack()`; `{kind:null}` → `navigate({page:'createPicker'})`; a top-level kind →
      `navigate({page:'create', kind, tab:'basics', preset})`; a child kind → `openContextPane({kind:'create', request})`.
  - `selectedIdOf(state): ArmId | null` (route resource id, or `flow:` for a flow pane). It replaces reads of
    `session.ui.selectedId`.
  - `bottomTab`, `selectTab`, `selectedId` and `creating` are removed in Task 8, once nothing uses them.

- [ ] Failing tests:
  - `navigate` / `goBack` round trip;
  - navigating to the same route doesn't grow `back`;
  - a breadcrumb for an NSG resource route is `Home > Network security groups > nsg-web`;
  - `routeForResource(subnetId)` gives the VNet with section `subnets`;
  - `goBack after create`: createPicker → create → navigate(resource) → `goBack()` gives the create route (the wizard
    keeps its own state; the page re-renders from route).
- [ ] Implement. The world's ARM helpers (`azure.parseArmId`, `parentResourceId`) give names and parents.
- [ ] Tests pass. Commit.
